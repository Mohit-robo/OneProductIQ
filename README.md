# OneProductIQ Demo Application

## Overview
The **OneProductIQ** demo application demonstrates a complete end‑to‑end workflow for:
- Uploading product images
- Using a **Fixed Prompt** to instruct an ONNX‑based FastVLM model
- Receiving structured metadata (product type, attributes, style, audience) generated by the model
- Displaying results in a clean, professional UI

The project follows a **modular, memory‑driven development approach** documented in `MEMORY.md`. All major decisions, trade‑offs, and future directions are recorded for transparency and future reference.

---

## Architecture Overview

```
+-------------------+       +-------------------+       +-------------------+
|   Frontend (Vite) | <---> |   Backend (Express) | <---> |   FastVLM (ONNX)   |
+-------------------+       +-------------------+       +-------------------+
        │                         │                           │
        │   • Image preview        │   • /prompts endpoint   │   • ONNX Runtime
        │   • Prompt selector*     │   • Prompt parsing      │   • Text generation
        │   • /upload POST         │   • /upload inference   │   • Return JSON/markdown
        │   • Display results       │   • Response formatting │
        └──────────────────────────┘                       └───────────────────┘
```

### Key Components

| Layer | Responsibility | Main Files |
|-------|----------------|------------|
| **Frontend** | React UI, image upload, prompt selection (now simplified to a single fixed prompt), result display | `demo-app-client/src/App.jsx`, `vite.config.js` |
| **Backend** | FastAPI‑style endpoint `/upload`, `/prompts`, serves prompt library | `demo-app/server.mjs` |
| **ML Model** | ONNX‑based FastVLM model (encoder → decoder) | Model files in `triton_server_test/` (kept for reference) |
| **Configuration** | Proxy rules for dev server, environment variables | `demo-app-client/vite.config.js` |

### Current State (as of 2026‑05‑03)

- **Prompt Management**: Simplified to a **single fixed prompt** (no dropdown).  
- **UI**: Professional sober design with slate‑50 background, indigo accents, responsive card‑based results.  
- **Image Preview**: Constrained to 128 px height with `object-contain` to preserve aspect ratio.  
- **Result Display**: Structured output rendered in card components; fallback to raw text when JSON parsing fails.  
- **Documentation**: `MEMORY.md`, `todo.md`, `lessons.md`, and `architecture_planning/0_session_summary.md` capture all decisions and lessons learned.

## Setup & Development

### Prerequisites
- **Node.js** (v18.19.1)  
- **npm** (or yarn)  
- **Git** (to clone the repository)

### Backend Setup
```bash
cd demo-app
npm install          # install dependencies
npm run dev          # starts server on http://localhost:3000
```

### Frontend Setup
```bash
cd demo-app-client
npm install          # installs React, Vite, and dependencies
npm run dev          # starts dev server on http://localhost:5173
```

### Environment
- The frontend proxies `/upload` and `/prompts` to `http://localhost:3000` via Vite config (`vite.config.js`).  
- Ensure the backend is running before starting the frontend.

### Running the Full Stack
1. Start the backend: `cd demo-app && npm run dev`  
2. In another terminal, start the frontend: `cd demo-app-client && npm run dev`  
3. Open `http://localhost:5173` in your browser and follow the UI workflow.

## Usage Flow

1. **Select Image** – Choose a product image file.  
2. **Upload** – Click *Upload & Describe* (or press Enter).  
3. **Processing** – Image is sent to the backend, forwarded to the FastVLM model, and a description is returned.  
4. **Results** – The UI shows a structured breakdown (type, category, attributes, style, audience) if the model response is JSON; otherwise it shows the raw text description.  

> **Note:** The dropdown selector has been removed; the app now always uses one predefined prompt, ensuring consistent and clean output.

## Future Enhancements (Roadmap)

- **Add More Prompt Templates** – administrators can upload additional `.txt` prompts; UI will dynamically populate the selector.  
- **Prompt Editing UI** – Back‑office UI for editing prompt text without code changes.  
- **Automated Testing** – Unit tests for `/upload` and `/prompts` endpoints; UI tests for component rendering.  
- **Versioned Prompts** – Store multiple versions, allow rollback to previous prompt definitions.  
- **Metrics Dashboard** – Track latency, token usage, and success rates for ongoing monitoring.

## Lessons Learned

- **Theme Synchronization is Critical** – All visual changes must be reflected in `index.css` to avoid stale styling.  
- **Single Source of Truth for Prompts** – Keeping prompt definitions in a central JSON structure eases maintenance.  
- **Documentation Saves Time** – Recording decisions in `MEMORY.md`, `lessons.md`, and `0_session_summary.md` prevents repeated re‑explanation.
